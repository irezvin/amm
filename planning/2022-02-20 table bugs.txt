-   Takeaways from implementing "twin view" based table
    
    -   it can be hard to develop universal support of several views of
        arbitrary elements due to different edge cases.
        
        Examples of such edge cases:

        -   resource that can be acquired by only one view at the moment
            (focused node is one example; scrollIntoView: which views to scroll to?)
            -   proposal: views-aware element (VAE)
                -   focusedView (was already done for `input`s); 
                -   primaryDimensionsView, primaryPositionView;
                -   syncPositionBetweenViews, syncDimensionsBetweenViews 
                -   etc
        -   displayParent has two views. We add an element that has *one* view
            into that displayParent. We can display one DOM node that way,
            and what do we have to do with another? (non-existent)
            -   proposal: clone view and DOM node, but for that to happen,
                all views should be cloneable
                    
    >   focus.
    
        Cell activation changes focus. 

        Table navigation changes active cell, changing the focused node.
        That will cause to node of the first view to be focused, since
        it reacts to the event first. But the proper way is that **the node
        that was interacted with (clicked) should receive the focus**.
                
        -   both proposed solutions are based on view-aware-view (VAV):
        
            X   A.  View aware element: table has activeTableView; 
                    clicking and focusing (interaction) set this property; 
                
            +   B.  we can set focus the Cell view that is related to the 
                    Table view that already has focus.

                    From viewpoint of the TD 1 of TABLE 1, it checks if
                    there are other views of same cell (i.e. TD 2 of TABLE 2),
                    and if table view of TABLE2 has the focus, we skip
                    request to focus TD 1, giving the way to TD 2 to acquire
                    the focus.
            
                +   somewhat look-alike to A, but "activeTableView" is determined
                    dynamically every time;

                ?   plus maybe, given the empty document.activeElement at the moment,
                    we can check for window.event.target (is this a thing)?
                    
    -   editor
        
        It makes sense to show it in the focused view and not in the first view,
        but for that, we need to properly assign the `parent`, and hide
        cell content in the view, and not in the cell!
