====== Events ======
Created Monday 14 September 2020


In the Amm, interaction between the objects is done using the Observer Pattern: object generates an event that multiple subscribers are then notified about. Logic of reacting to the event is contained in the handler method.

===== out<EventName> - standard name for event-generating method =====

To ease locating what events are supported by a particular class in the source code, names of every event-generating method start with "out" prefix, and ends with the name of the event (with the first captial letter). Parameters of the method are parameters of the event.

The body of such methods are usually one-liner this._out('eventName', arg1, arg2...), that implements calling the observers (_out is defined in Amm.WithEvents).

Typical definition of the event looks like this:

{{{code: lang="js" linenumbers="False"
outValueChange: function(value, oldValue) { // name of the event starts with the capital letter here
    return this._out('valueChange', value, oldValue); // but with lowercase one here
}
}}}

===== Amm.WithEvents =====

Almost all event-related code is located in Amm.WithEvents; all event-generating classes are descendants of this class.

Important to know: parameters of ''subscribe'', ''getSubscribers'' and ''unsubscribe'' methods are the same. But the core difference of ''getSubscribers()'' and ''unsubscribe()'' from ''subscribe()'' is that the former two can accept ''undefined'' as any of the arguments, that means "any" - so, for example, ''foo.unsubscribe('valueChange')'' will unsubscribe all subscribers to that event.

==== Amm.WithEvents.prototype.hasEvent (eventName) ====
* returns true, if object supports event with the name **eventName**, and false, if not
* **eventName** - string - name of the event (starting from the lowercase!)
* implementation just checks that the method "out + 'EventName'" is present in the current object

==== Amm.WithEvents.prototype.subscribe(eventName, handler, scope, extra) ====
* subscribers the hanlder method **handler** of the object **scope** to the event **eventName**; the ''extra'', if supplied, will be added as the last argument when calling the handler.
* **eventName: string** - name of the event. Attempt to subscribe at non-existent event triggers an exception with the text "No such event: 'eventName'". In some classes it is possible to subscribe to arbitrary events. See below: //Amm.WithEvents.strictEvents, Amm.WithEvents._handleMissingEvent()//
* **handler: string|function|object** - string or function (or any object that has ''apply()'' method) - the handler
	* if it's a function, it's called with ''scope'' as the ''this'' (or, if ''scope'' is null, with the event-emitting object as the ''this'')
	* if it's an object, method ''handler.apply.apply(scope, [arg1, arg2, ...extra])'' is called
	* if it's a string, method of the ''scope'' object with the matching name (''scope[handler]'') will be called
		* if scope doesn't have such method, exception will be triggered
* **scope** - the subscriber-object, that will serve as ''this'' during the event handling call
* **extra** - additional argument (any) sent as the last argument to the handler. If not supplied, ''null'' is used.
* the function is idempotent: if subscriber with the exact same values of ''handler'', ''scope'' and ''extra'' is already registered, it won't be registered again
* returns ''true'' if new subscriber was added, and ''undefined'' if it wasn't (because it already existed).

==== Amm.WithEvents.prototype.getSubscribers(eventName, handler, scope, extra) ====
* returns subscribers to the events of the object
	* ''eventName'', ''handler'', ''scope'', ''extra'' have the same sense as with ''subscribe()'', except for how ''undefined'' values are handled
	* if ''undefined'' is supplied as eventName, handler, scope, or extra, then the filtering by the given argument is not made, and all subscribers disregarding to what the value of specified handler' part is, are returned
	* for example, Amm.WithEvents.getSubscribers(undefined, undefined, someObject) finds all subscribers with ''scope === someObject'' - for any ''events'', ''methods'' and ''extra''
	* Amm.WithEvents.getSubscribers() returns all subscribers
* **eventName: string|undefined** - name of the event or ''undefined'' to match all events
* **handler: function|object|string|undefined** - function handler, object handler, method name, or ''undefined'', to match any handler
* **scope: object|null|undefined** - scope object, or ''null'' to find handlers without defined scope, or ''undefined'' to match any scope
* **extra: mixed|null|undefined**
	* **mixed** - subscribers with matching ''extra'' will be returned
	* **null** - subscribed without extra defined at subscribtion (or with ''null'' explicitly provided) will be returned
	* **undefined** to match any ''extra''
* returns array of arrays, where every sub-array corresponds to one subscription
	* the format is [handler, scope, extra, eventName, index]
	* ''eventName'' - name of the event
	* ''index'' - ordinal number of this subscription amonth all subscription to event ''eventName''
	* important! order in this array is different from the order of the arguments of subscribe/unsubscribe/getSubscribers
* if there is no such event, or there are no subscribers, empty array is returned

==== Amm.WithEvents.prototype.unsubscribe (eventName, handler, scope, extra) ====
* unsubscribes all subscribers that match the provided eventName, handler, scope, extra criteria
* semantics of the arguments is the same as for getSubscribers (since ''unsubscribe()'' uses ''getSubscribers()'' under the hood)
* returns the same array as in ''getSubscribers()''
* returns empty array if there is no such event, doesn't generate the exception

==== Amm.WithEvents.prototype.unsubscribeByIndex (eventName, index) ====
* unsubscribes subscription with given **index** to the event **eventName**
* **eventName: string** - event name, required, cannot be ''undefined''
* **index: number** - order of the subscription within this 'eventName'' (last value in the result subarray returned by ''getSubscribers()'')
* result is the same as for getSubscribers() or unsubscribe(), but has at most one element
	* if there is no such event, the exception isn't thrown

==== Amm.WithEvents.prototype.getUniqueSubscribers (classOrInterface, eventName) ====
* returns unique ''scope'' objects of subscription to a single or all events of the given object
* **classOrInterface: undefined|string|array:** 
	* **undefined**: returns all scopes
	* **string|Array**: returns scopes that match given class/interface or one of provided classes/interfaces, if the Array of strings is provided
* **eventName: undefined|string**
	* undefined - returns scopes for all events
	* string - returns scopes only for provided event
* returns unique non-null subscriber scopes to the event ''eventName'', or empty array, if there is no such event, or no subscribers
* for example 
	* to find all Views of the element, call ''element.getUniqueSubscribers('Amm.View.Abstract')''
	* to find all Expressions, subscribed to any properties of the given element, call ''element.getUniqueSubscribers('Amm.Expression')''

==== Amm.WithEvents.prototype._out(eventName, args...) ====
* calls handler functions, subscribed to the event **eventName**
	* for semantics, see the description of Amm.WithEvents.subscribe()
* all extra arguments (arg1, arg2 and so on) are passed to the handlers
* also, every handler receives ''extra'' parameter of ''subscribe()'' call, if it was provided during the subscription - or null otherwise
* during the method invocation, Amm.event object gets populated with the event-related information (the description is below)

==== Amm.event ====
* global object, that contains information about the currently handled event. Might be useful, if we use a universal handlers that react to events of different types - from different sources.
* **Amm.event.origin**: **object** - object that triggered the event
* **Amm.event.name**: **string** - name of the current event
* **Amm.event.args**: **Array** - arguments that will be passed to the handler functions (including the trailing extra)
* **Amm.event.parent**: **object** - ''event'' structure with the information of the event, during the handling of which the current event was triggered (null for the most outermost event)

==== Amm.WithEvents(options, initOnHandlersOnly): constructor ====
* **options: object|null|undefined** - options (proto hash) of the WithEvents instance
	* options are passed to Amm.init(this)
	* options can contain special keys in the form on__<eventName>
	* **important!** options hash is modified during the execution - by deleting on__ keys - to avoid passing it to the constructor part that sets the properties
* **options.on__eventName: function|Array**: creates subscribers to the events during the instance creation
	* **function** - same as this.subscribe(eventName, options.on__eventName)
	* **Array [handler, scope, extra]** - from one to three elements are expected (see Amm.WithEvents.prototype.subscribe)
* **initOnHandlersOnly: boolean** - if true, Amm.init isn't called to set properties of the instance, only on__ handlers are set - intended for usage in the inherited classes for fine-grained control of the objects' initialization stages.

==== Calling WithEvents constructor during the inheritance ====

**First,** all methods of Amm.WithEvents expect the ''_subscribers'' array to exist. The event assignment can happen quite early - incl. during the initialization.

**Second,** by default Amm.WithEvents attempts to set all [[properties]] passed to the ''options'' with ''Amm.init()''. If we will call WithEvents early in the constructor, then some structured needed for this might not be initialized yet.

There are two possible solutions:
a. Very early in the descendant constructor call ''Amm.WithEvents()'' with empty values, to create _subscribers, and leter call it with options

b. At the very start, use ''initOnHandlersOnly'' parameter: call Amm.WithEvents(options, true), and later - just call Amm.init(this, options) (given that on__ keys will be removed from ''option'' on call that inits handlers)

==== Future-proof method of receiving ''extra'' param in the event handler ====
* ''extra'' is always the last method of the handler function.
* ''extra'' is always sent, even if it wasn't provided during the subscription (in that case it's null)
* in case we specify ''extra'' in the parameter list, we risk mismatch, in case the event is later extended with additional arguments
* therefore, it's recommended to receive the last parameter like this:

{{{code: lang="js" linenumbers="False"
function handlerFn(eventArg1, eventArg2) {
	var extra = arguments[arguments.length - 1];
	console.log(extra);
}
}}}

==== Helper (internal) properties and methods to work with subscription/unsubscription to events of the current object ====

=== Amm.WithEvents.prototype.strictEvents ===
* **boolean**, default === true
* if set to false, non-existing events will be created on first subsciption attempts; _handleMissingEvent() won't be used

=== Amm.WithEvents.prototype._handleMissingEvent: function(eventName, handler, scope, extra) ===
* blank template method to be overriden in subsclasses when needed;
* called when subscribing to non-existent events when this.strictEvents === true;
* same arguments as for subscribe();
* return value tells subscribe() how to behave:
	* **undefined**: event not found, subscribe() should generate exception
	* **true**: subscribe() will register the handler
	* **false**: subscribe() won't fail (and will report that the event was registered), but won't do anything, assuming that _handleMissingEvent did all the work

=== Amm.WithEvents.prototype._subscribeFirst_<eventName>() ===
* if method with the matching name exists, it will be called when number of subscriptions to this event changes from zero to non-zero
* is useful if we need to initialize some structures dedicated solely for the purpose of this event

=== Amm.WithEvents.prototype._unsubscribeLast_<eventName>() ===
* vice-versa: called when number of subscribers for given event changes from non-zero to zero
* useful to remove the structures that were created for the purpose of the event - i.e. in _subscribeFirst_<eventName>()

===== Examples =====

==== Creating new class with own events ====

**Footnote.** In the example below we directly call .out<Event> methods of the instances. It's not corrent, the object should generate the events on its' own, but here it's done for the illustrative purpose.

{{{code: lang="js" linenumbers="False"
SchoolClass = function(options) {
	// since we don't have any special logic in the constructor, that's enough
	Amm.WithEvents.call(this, options);
};

SchoolClass.prototype = {
	'SchoolClass': __CLASS__,
	id: null,
	outDayStart: function(date) {
		return this._out('schoolDayStart', date);
	},
	outLesson: function(lessonName, duration) {
		return this._out('lesson', lessonName, duration);
	},
	outBreak: function(duration) {
		return this._out('break', duration);
	},
	outDayEnd: function() {
		return this._out('dayEnd');
	}
};

Amm.extend(SchoolClass, Amm.WithEvents);
var newClass = new SchoolClass();

//>
newClass.hasEvent('dayStart');

//< true

//>
newClass.hasEvent('DayStart'); 

//< false // names of events cannot start from the upper-case letter

//>
newClass.hasEvent('someNonExistentEvent');
//< false

//>
newClass.getUniqueSubscribers();
//< [] // no handlers yet

MyHandlerObject = {
	handleDayStart: function(date) {
		console.log ('day started', date);
	},
	handleLesson: function(lessonName, duration) {
		console.log('lesson', lessonName, duration);
	},
	displayExtra: function() {
		// example how to get ''extra'' value
		var extra = arguments[arguments.length - 1];
		if (extra !== undefined) console.log("extra is", extra);
	},
	handleAnything: function() {
		console.log.apply(console, [Amm.event.name].concat(Amm.event.args));
	}
}

newClass.subscribe('dayStart', MyHandlerObject.handleDayStart, MyHandlerObject);

// second way: provide name of the method instead of the method
newClass.subscribe('lesson', 'handleLesson', MyHandlerObject);

// provide extra
newClass.subscribe('lesson', myHandlerObject.displayExtra, myHandlerObject, 'A boring thing');

// provide a different extra
newClass.subscribe('lesson', myHandlerObject.displayExtra, myHandlerObject, 'Whatever');

//>
newClass.getUniqueSubscribers();

//< [myHandlerObject]

//>
newClass.getSubscribers('lesson');

//< [ 
//<     ['handleLesson', myHandlerObject, null, 'lesson', 0], 
//<     [function displayExtra, myHandlerObject, 'A boring thing', 'lesson', 1],
//<     [function displayExtra, myHandlerObject, 'Whatever', 'lesson', 2]
//< ]

//>
newClass.outDayStart('2020-01-01');

//< 'day started', '2020-01-01'

//>
newClass.outLesson('math', '30m');

//<< 'lesson', 'math', '30m'
//<< 'A boring thing'
//<< 'Whatever'

// unsubscribing all handlers with extra === 'A boring thing'

//>
newClass.unsubscribe(undefined, undefined, undefined, 'A boring thing')

//< [ 
//<     [function displayExtra, myHandlerObject, 'A boring thing', 'lesson', 1]
//< ]

// only one handler now fires:

//>
newClass.outLesson('math', '30m');

//<< 'lesson', 'math', '30m'
//<< 'Whatever'

// unsubscribing all handlers with scope === 'myHandlerObject'
//>
newClass.unsubscribe(undefined, myHandlerObject)

//< [ 
//<     ['handleLesson', myHandlerObject, null, 'lesson', 0], 
//<     [function displayExtra, myHandlerObject, 'Whatever', 'lesson', 1]
//< ]

//> newClass.outLesson('math', '30m');

//<<

// Let's define handlers in the options

var anotherClass = new SchoolClass({

	// provide a handler function
	on__dayStart: function(date): { console.log ("DS", date); },

	// set scope and extra:
	on__lesson: [ myHandlerObject.displayExtra, myHandlerObject, 'Lesson goes brrr' ]
});

//>
anotherClass.outDayStart('2020-01-01');

//<< 'DS',  '2020-01-01'

//>
anotherClass.outLesson('media', '25m');

//<< 'Lesson goes brrr'

}}}
